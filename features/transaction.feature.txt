Feature: Transaction Data Quality
  As a Data Quality Engineer
  I want to validate transaction data at each pipeline layer
  So that only clean transaction data reaches reporting

  Background:
    Given the database is connected
    And the ETL pipeline has run

  Scenario: Raw transactions are loaded into Bronze layer
    Given the raw_transactions table has data
    When I check the Bronze transaction layer
    Then Bronze should have the same count as raw transactions
    And all transaction DQ flags should be populated

  Scenario: Null amounts are flagged in Bronze
    Given the raw_transactions table has null amounts
    When I check the Bronze transaction layer
    Then transactions with null amounts should have flag "MISSING_AMOUNT"

  Scenario: Negative amounts are flagged in Bronze
    Given the raw_transactions table has negative amounts
    When I check the Bronze transaction layer
    Then transactions with negative amounts should have flag "NEGATIVE_AMOUNT"

  Scenario: Invalid currencies are flagged in Bronze
    Given the raw_transactions table has invalid currencies
    When I check the Bronze transaction layer
    Then transactions with invalid currencies should have flag "INVALID_CURRENCY"

  Scenario: Future dates are flagged in Bronze
    Given the raw_transactions table has future dates
    When I check the Bronze transaction layer
    Then transactions with future dates should have flag "FUTURE_DATE"

  Scenario: Bad transactions are removed in Silver layer
    Given the Bronze transaction layer has flagged records
    When I check the Silver transaction layer
    Then Silver should have fewer transactions than Bronze
    And all Silver amounts should be positive
    And all Silver currencies should be valid

  Scenario: Orphan transactions are removed in Silver layer
    Given the raw_transactions table has orphan records
    When I check the Silver transaction layer
    Then transactions with no matching customer should not exist

  Scenario: Silver transactions have no duplicate IDs
    Given the Silver transaction layer has data
    When I check for duplicate transaction IDs
    Then duplicate transaction IDs should be reported as findings

  Scenario: Gold daily summary aggregates Silver transactions
    Given the Silver transaction layer has data
    When I check the Gold daily summary
    Then Gold should have one row per currency per day
    And total amount in Gold should match Silver totals
    And transaction count in Gold should match Silver count

  Scenario: Gold daily summary has no null aggregations
    Given the Gold daily summary has data
    When I check for null values in Gold daily summary
    Then total_amount should never be null
    And total_transactions should never be null
    And currency should never be null
