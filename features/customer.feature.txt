Feature: Customer Data Quality
  As a Data Quality Engineer
  I want to validate customer data at each pipeline layer
  So that only clean customer data reaches reporting

  Background:
    Given the database is connected
    And the ETL pipeline has run

  Scenario: Raw customers are loaded into Bronze layer
    Given the raw_customers table has data
    When I check the Bronze customer layer
    Then Bronze should have the same count as raw customers
    And all DQ flags should be populated

  Scenario: Invalid emails are flagged in Bronze
    Given the raw_customers table has null emails
    When I check the Bronze customer layer
    Then customers with null emails should have flag "MISSING_EMAIL"

  Scenario: Invalid phone numbers are flagged in Bronze
    Given the raw_customers table has invalid phones
    When I check the Bronze customer layer
    Then customers with invalid phones should have flag "INVALID_PHONE"

  Scenario: Missing names are flagged in Bronze
    Given the raw_customers table has missing names
    When I check the Bronze customer layer
    Then customers with missing names should have flag "MISSING_NAME"

  Scenario: Bad customers are removed in Silver layer
    Given the Bronze customer layer has flagged records
    When I check the Silver customer layer
    Then Silver should have fewer customers than Bronze
    And all Silver customers should have valid emails
    And all Silver customers should have valid names

  Scenario: Silver customers have no duplicate IDs
    Given the Silver customer layer has data
    When I check for duplicate customer IDs
    Then duplicate customer IDs should be reported as findings

  Scenario: Gold customer summary contains all Silver customers
    Given the Silver customer layer has data
    When I check the Gold customer summary
    Then every Silver customer should appear in Gold
    And total spend should be calculated for each customer
